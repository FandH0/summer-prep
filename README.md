# summer-prep

Подготовка к стажировке Python-разработчиком: углублённая практика языка,
тестирования и алгоритмов.

Работа над каждой задачей шла по циклу: самостоятельное решение с нуля →
тесты → код-ревью → исправления отдельными коммитами → повторное ревью.
Ревью проводилось не чтением кода, а прогоном: запуск тестов и линтеров,
проверка краевых случаев, замеры на предельных входах, перебор против
эталонной реализации. Каждый найденный баг превращался в регрессионный тест,
поэтому история коммитов показывает не только решения, но и то, как они
дорабатывались.

## Запуск

```bash
pip install pytest flake8

pytest          # 206 тестов
flake8 .        # линтер
```

Конфигурация в `pyproject.toml` (`pythonpath`, `testpaths`) и `.flake8`.
Запускать можно из любой директории репозитория — rootdir определяется по
`pyproject.toml`.

### A1. Класс `Vector`

Двумерный вектор с поддержкой `v1 + v2`, `v1 - v2`, `v * 3`, `v1 == v2`,
`abs(v)`, `str(v)` → `"(x, y)"`, `v1 @ v2` (скалярное произведение через
`__matmul__`).

Ключевое: бинарные операторы возвращают `NotImplemented` для чужих типов, а не
бросают исключение — это позволяет Python попробовать зеркальную операцию и
сформировать корректный `TypeError` самостоятельно. Объект неизменяем
(`@dataclass(frozen=True)`), поэтому его безопасно использовать как ключ словаря.

### A2. Иерархия `Shape`

Базовый класс с абстрактным `area()`, наследники `Circle`, `Rectangle`,
`Triangle` (формула Герона). `total_area(shapes)` суммирует площади любых фигур.

Ключевое: `ABC` + `@abstractmethod` вместо `raise` в `__init__` — контракт
проверяется при создании объекта, и подкласс без `area()` инстанцировать нельзя.

### A3. Генератор `chunked(iterable, n)`

Разбивает итерируемый объект на куски по `n` элементов:
`list(chunked(range(7), 3))` → `[[0,1,2], [3,4,5], [6]]`.

Ключевое: вход не материализуется — функция работает с бесконечными
генераторами. Остаток отдаётся после цикла только если непустой (иначе на длине,
кратной `n`, появляется лишний `[]`).

### A4. Частотный словарь

Топ-5 частых слов текста без учёта регистра и пунктуации. Две реализации:
через `collections.Counter` и вручную через `defaultdict(int)`.

Ключевое: пунктуация вычищается через `str.maketrans` + `string.punctuation`, а
не перечислением символов вручную.

### A5. Скользящий максимум

Максимум в каждом окне размера `k`. Наивно за O(n·k) и через монотонный
`collections.deque` за O(n), с замером времени на 10⁶ элементов.

Ключевое: обе реализации согласованы, включая `k > n` (окон нет → пустой
результат). Дек хранит индексы, а не значения, — иначе нельзя определить, что
элемент вышел за границу окна.

### A6. Класс `Money`

Неизменяемый value object: сумма в копейках (целое) + валюта. Арифметика,
полный набор сравнений, хеширование, `str` → `"120.50 RUB"`.

Ключевое: сумма хранится целым числом, форматирование целочисленное через
`divmod` — `float` не появляется нигде, в том числе на отрицательных суммах
(`-5` → `"-0.05 RUB"`, а не `"-1.95 RUB"`: `//` и `%` в Python округляют вниз).
Сложение разных валют → `ValueError`, чужой тип → `NotImplemented`.

### A7. Декораторы

- `@timed` — замер времени выполнения;
- `@retry(times, delay, exceptions)` — повтор при исключении, декоратор
  с параметрами;
- `@memoize` — кэширование результата по аргументам.

Ключевое: `retry` — фабрика декораторов (три уровня вложенности), настройки
живут в замыкании, счётчик попыток — в обёртке, чтобы обновляться на каждый
вызов. Пауз ровно `times - 1`. Ключ кэша в `memoize` — кортеж
`(args, tuple(sorted(kwargs.items())))`, а не хеш: словарь хеширует сам и
дополнительно сравнивает ключи, а голый `hash()` даёт коллизии
(`hash(-1) == hash(-2)`).

### A8. Контекстные менеджеры

`Timer` (класс с `__enter__`/`__exit__`) и `func_timer`
(`@contextlib.contextmanager`) — одинаковое наблюдаемое поведение, тесты
параметризованы по обеим реализациям. Плюс `suppress_and_log` — подавление
указанных исключений с логированием.

Ключевое: в генераторном варианте `try/finally` обязателен — при исключении в
теле блока `contextmanager` бросает его внутрь генератора в точку `yield`, и код
после `yield` не выполняется. Наружу через `yield` отдаётся объект-держатель:
переприсваивание имени внутри генератора вызывающий не увидит, а мутация
атрибута — увидит.

### A9. Ленивый конвейер обработки лога

Цепочка генераторов для файла журнала произвольного размера:

```
read_lines → parse → filter_level → take → top_modules / group_by_date
```

Формат записи: `2026-07-22T10:15:00 ERROR auth: invalid token`.
Битые строки пропускаются, не роняя конвейер.

Ключевое: ни на одном шаге файл не загружается целиком — проверено тестами со
шпионом на потребление и на бесконечном источнике. Валидация аргументов
вынесена в обычную функцию, возвращающую генератор: тело генератора выполняется
только при первом `next()`, поэтому проверки внутри него сработали бы слишком
поздно. `groupby` требует отсортированного входа — поведение на
неотсортированном зафиксировано отдельным тестом.

### A10. LRU-кэш за O(1)

Три реализации общего интерфейса (`get`, `put`, `__len__`, `__contains__`,
`keys_in_lru_order`):

- `LRUCacheLinked` — словарь + двусвязный список с sentinel-узлами;
- `LRUCacheOrdered` — на `collections.OrderedDict`;
- `LRUCacheNaive` — список + словарь, O(n), эталонная модель.

Ключевое: третья реализация написана так, чтобы корректность была очевидна при
чтении, и служит оракулом для дифференциального теста — 10 000 случайных
операций подаются во все три, после каждой сверяются результат, длина и порядок
LRU. Это ловит то, что не поймает набор придуманных вручную случаев: две
собственные реализации могут ошибаться одинаково, а независимо написанная
модель — вряд ли.

## Подход к тестированию

Что применяется в тестах и зачем:

- **`parametrize`** — включая двойной и по классам-реализациям: один набор
  проверок гарантирует, что разные реализации одного контракта ведут себя
  одинаково.
- **Фикстуры** — `tmp_path` для файлов, `monkeypatch` для подмены `time.sleep` и
  часов, `capsys` для перехвата вывода, собственные через
  `@fixture(params=...)`.
- **Тесты-шпионы** — источник, считающий, сколько из него вытащили; единственный
  способ проверить ленивость, потому что результат у ленивой и жадной версии
  одинаковый.
- **Дифференциальное тестирование** — сверка против заведомо корректной
  медленной модели с фиксированным seed.
- **Регрессионные тесты** — каждый найденный на ревью баг превращается в
  отдельный тест.

Правила, выведенные из разбора собственных ошибок:

1. Happy path ничего не доказывает. Обязательный минимум границ: пусто, один
   элемент, всё одинаковое, параметр больше входа, длина кратна параметру,
   неверный тип.
2. Сверка двух собственных реализаций между собой — не тест: обе могут
   ошибаться одинаково. Нужен независимый эталон.
3. Если ради прохождения теста приходится дописывать спецветку в алгоритм —
   сломана семантика, а не тест.
4. `raises(Exception)` слишком широк: он поймает и `AttributeError` от опечатки.
   Проверять конкретный тип, при необходимости с `match=`.
5. Добавленный код без теста — почти наверняка с багом.

## Блок B — алгоритмы в формате контеста

Задачи решаются в контестном режиме: ввод из `stdin`, вывод в `stdout`, лимит
40 минут на задачу. Тестов и линтеров здесь нет намеренно — код одноразовый,
его читает только чекер. Проверка ведётся прогоном на примерах из условия,
краевых входах и переборе против наивного эталона.

### Запуск

```bash
echo "5 9
2 7 11 15 4" | python week2/B1.py
```

| № | задача | техника | сложность |
|---|---|---|---|
| [B1](week2/B1.py) | два числа с заданной суммой | хеш-таблица, один проход | O(n) |
| [B2](week2/B2.py) | количество групп анаграмм | канонический ключ | O(Σ\|w\|) |
| [B3](week2/B3.py) | длиннейшая подстрока без повторов | скользящее окно переменной длины | O(n) |
| [B4](week2/B4.py) | сортировка массива из 0, 1, 2 | Dutch National Flag, три указателя | O(n), O(1) памяти |
| [B5](week2/B5.py) | максимум суммы окна длины k | скользящее окно фиксированной длины | O(n) |
| [B6](week2/B6.py) | корректность скобочной последовательности | стек | O(n) |

### B1. Два числа

Ключевая идея: искать нужно среди **уже просмотренных** элементов. Для текущего
`x` проверяем, встречалось ли ранее дополнение `S - x`; если нет — кладём `x` в
словарь и идём дальше.

Порядок «сначала проверить, потом вставить» принципиален: при обратном порядке
элемент найдёт сам себя, и на входе `S = 8`, массив `[4]` вернётся неверный
ответ `0 0`.

### B2. Анаграммные группы

Задача сводится к вопросу: какое представление слова одинаково у всех анаграмм и
различно у не-анаграмм? Такое представление называют канонической формой.

Использован кортеж из 26 счётчиков букв — O(k) на слово против O(k log k) у
сортировки букв. Замер на 10⁵ словах суммарной длиной 5 МБ:

| ключ | время |
|---|---|
| кортеж счётчиков | 0.62 с |
| `tuple(sorted(word))` | 0.71 с |
| `frozenset(Counter(word).items())` | 3.65 с |

Последний вариант выглядит идиоматичнее всех и медленнее всех — наглядный
пример, почему на контесте выбирают не по красоте.

Ключ обязан быть хешируемым, поэтому список не подходит.

### B3. Длиннейшая подстрока без повторов

Скользящее окно переменной длины: правая граница двигается всегда, левая — пока
нарушен инвариант «в окне нет повторов». Состояние окна хранится в `set`.

Вложенный `while` внутри `for` не делает решение квадратичным: левая граница
только растёт и ограничена `n`, значит суммарное число сужений не превышает `n`.
Это амортизационный аргумент — стандартный вопрос после того, как решение
написано.

Проверка на худшем случае (10⁵ одинаковых символов, окно схлопывается на каждом
шаге) — 0.076 с.

### B4. Сортировка цветов

Массив делится на четыре зоны, границы которых и есть указатели:

```
[ нули | единицы | не рассмотрено | двойки ]
        ^         ^                ^
       low     current           high
```

Инвариант: левее `low` только нули, между `low` и `current` только единицы,
правее `high` только двойки. Каждый шаг смотрит на `nums[current]` и выбирает
действие, сохраняющее инвариант.

Ключевая тонкость: после обмена с `high` на позицию `current` приходит
**нерассмотренный** элемент, поэтому `current` двигать нельзя. После обмена с
`low` приходит уже разобранный элемент — двигать можно. Эта асимметрия и есть
суть алгоритма.

Первая версия решения была написана без явного инварианта и проваливала 13
входов из 1092 при полном переборе всех массивов длины до 6 — элементы между
указателями выпадали из рассмотрения. Задача переписана с нуля от инварианта.

### B5. Максимум суммы окна длины k

Первое окно суммируется честно за O(k), дальше сумма пересчитывается
инкрементально: `+= nums[i] - nums[i - k]`.

Ответ инициализируется суммой первого окна, а не нулём: элементы могут быть
отрицательными, и на входе `-5 -2 -8 -1 -9` при `k = 1` правильный ответ `-1`, а
не `0`.

### B6. Валидные скобки

Стек хранит незакрытые открывающие скобки, словарь отображает закрывающую в
парную ей открывающую.

Три места, где решение обычно ломается, и все проверены: снятие с пустого стека
(строка `)`), непустой стек в конце (строка `(`), несоответствие типа при
формально сбалансированном количестве (строка `([)]`).

Конструкция `for...else` здесь использована по назначению: блок `else`
выполняется, если цикл прошёл без `break`, то есть если ни одна скобка не
нарушила порядок по ходу.

### Что показал этот блок

Алгоритмическая часть решений оказалась стабильно верной; ошибки
сконцентрировались на границе с потоком ввода-вывода:

- `s[:-1]` вместо `rstrip("\n")` — срез убирает последний символ безусловно и
  портит строку, если завершающего перевода строки нет;
- `print(nums)` вместо `print(*nums)` — вывод `[0, 0, 1]` вместо `0 0 1` даёт
  неверный ответ при полностью корректном алгоритме;
- `sys.stdin.read()` без `rstrip` — перевод строки попадает в обрабатываемые
  данные.

Отсюда два правила, применяемых теперь по умолчанию: прогонять ввод в двух
вариантах (с завершающим переводом строки и без него) и сверять вывод с примером
из условия посимвольно.

Второе — проверка перебором вместо проверки примерами. Для задач с малым
алфавитом значений полный перебор входов небольшой длины против встроенного
эталона занимает десять строк и находит то, что не находят придуманные вручную
случаи:

```python
for combo in itertools.product([0, 1, 2], repeat=n):
    assert solve(list(combo)) == sorted(combo)
```

Это перенос идеи независимого оракула из блока A (`LRUCacheNaive`) в контестный
контекст.
